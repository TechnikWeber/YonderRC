LTE

Most data SIMs need only the APN. Add a PIN if your SIM is locked, and username/password only if your carrier requires APN auth. PIN/password are stored on the vehicle and never shown again.

SIM PIN management

Changes the PIN on the SIM itself. Leave "New PIN" empty to remove the PIN lock (no PIN). This is separate from the stored PIN above (used only to auto-unlock at connect).


        

      


      

        
LTE stick (HiLink)

        
Huawei sticks like the E3372h-320 are their own little router: they dial by themselves and never appear in ModemManager, so the LTE panel above stays empty for them. This reads the stick's own API instead. The interface is found through the routing table, so a LAN on another eth can't be mistaken for it.

          Open the stick's UI ↗
        

        
The stick's own network (192.168.8.0/24) is reachable only from the Pi. With a port set, the vehicle passes the stick's configuration page through, so you can open it from the hotspot, the LAN or the VPN instead of putting a keyboard on the vehicle — APN, SIM PIN and network mode live in the stick. If an API secret is set, open it once as …:PORT/?secret=YOUR_SECRET; the vehicle then remembers it in a cookie. Leave the port empty to keep the stick's admin page off the network.

Setup hotspot

        

          
          
        

        
        

          
          
          
        

        
The hotspot is open by default so the captive portal can put this page in front of you with nothing to type — set a password (min. 8 characters) once the vehicle leaves the bench, and an API secret above if the network isn't yours. Since v1.41.0 it runs in always: it comes up whenever the WiFi radio is free, next to Ethernet or LTE, so you can always reach the vehicle. It can never run while the Pi is joined to a WiFi network — one radio can't do both.

Native driver modules

        
Reading module status…

        
Installed here, not in a terminal. They are compiled on the Pi, so the vehicle needs internet for it (WiFi or LTE — its own hotspot has no uplink), and it takes a minute. Without the module the matching driver/sensor falls back to sim. Note that installing one builds all three: they are optional dependencies of the same package and npm always reifies them together — harmless, nothing uses a module unless you select that driver.

        

        


        

          
          
        

        
        

          
          
        

        

        

      


      

        
Security (optional)

        
Optional shared secret. When set, saving settings here and the control link both require it — in the ground app, enter it in the “secret” field next to the address; here you'll be prompted. Off by default, so first-time connect and setup need nothing.

        
        

          
          
          
        

        

        

      


      

        
CSI camera module

        

          Which sensor sits on the Pi's camera port. Only the official Raspberry Pi cameras are
          found automatically; an Arducam needs an explicit device-tree overlay, which lives in
          the firmware config and is therefore only read at boot. Picking one here writes that
          for you — no SSH — and tells you when a reboot is due.

Telemetry (voltage / current / battery)

        

          
          
        

        
Voltage channels

        

        

        
Current channels

        

        

        
The channel marked primary drives the battery %, the mAh/Wh counting, the low-battery warning and the blackbox columns. With one channel of a kind there is nothing to choose; with several, mark the one that measures the pack.

        
Temperature channels

        

        

        
Optional. Shown in the OSD below voltage/current; each value can be hidden per ground device under FPV › ⚙ › Sensor values. Give short labels (T1, Motor, ESC) — they are only shown once a kind has more than one channel.

        

          
          
        

        
        
        
The INA228 integrates charge and energy in hardware at ADC rate, so the mAh no longer depend on the polling rate or on samples this loop missed. Every other sensor (incl. INA237/238) is integrated on the Pi — "sensor" then falls back to "pi".

        

          
          
        

        
        
"voltage"/"clamp" need the full & empty voltage above. mAh (consumed/remaining) is unaffected — this only changes what the % gauge uses.

        

          
          
        

        

      


      

        
GPS

        

          
          
        

        

          
          
        

        
        

          
          
          
        

        
Common receivers: Adafruit Ultimate GPS, u-blox NEO-6/7/8/M9, BN-880 — most speak NMEA at 9600 baud over UART (use /dev/ttyAMA0 or /dev/serial0). USB dongles are easiest via gpsd. Manual home is saved; auto-home lasts for the session (takeoff point).

Update source

        

          
          
        

        

        
Defaults to this vehicle's own origin / main. Point it at a fork or a branch by entering a git remote name or a full URL (e.g. https://github.com/you/YonderRC.git) — useful for testing your own build on the vehicle.

        
Does what an SSH session would: git pull --ff-only, installs changed dependencies, rebuilds the control app when it changed, then restarts the vehicle service — so you can update from a field with nothing but this page. The vehicle needs internet for it. If a step fails, it stops there and keeps running the version you have.
