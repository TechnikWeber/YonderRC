What “Update & restart” does

Does what an SSH session would: git pull --ff-only, installs changed dependencies, rebuilds the control app when it changed, then restarts the vehicle service — so you can update from a field with nothing but this page. The vehicle needs internet for it. If a step fails, it stops there and keeps running the version you have.

LTE stick (HiLink)

        

          Why a HiLink stick needs its own panel
          
Huawei sticks like the E3372h-320 are their own little router: they dial by themselves and never appear in ModemManager, so the LTE panel above stays empty for them. This reads the stick's own API instead. The interface is found through the routing table, so a LAN on another eth can't be mistaken for it.

          Open the stick's UI ↗
        

        

          What the port does — the stick's own page, reachable from here
          
The stick's own network (192.168.8.0/24) is reachable only from the Pi. With a port set, the vehicle passes the stick's configuration page through, so you can open it from the hotspot, the LAN or the VPN instead of putting a keyboard on the vehicle — APN, SIM PIN and network mode live in the stick. If an API secret is set, open it once as …:PORT/?secret=YOUR_SECRET; the vehicle then remembers it in a cookie. Leave the port empty to keep the stick's admin page off the network.

        

        

      


      

        
Mobile data budget

        
…

        

          A video link empties a data plan quietly — this is the warning
          
An FPV stream costs roughly 0.5–1 GB per hour. Nothing announces that the plan is running out; the first symptom is that the vehicle is gone. Set the plan's allowance here and the OSD shows ⚠ DATA once the configured share is spent — the same idea as the low-voltage warning.

        

        
        
        

          Which of the two to pick
          
The vehicle sums the byte counters of every interface that carries traffic outwards, so it also catches a phone hotspot or a tethered laptop. It deliberately does not count the vehicle's own WiFi hotspot — a ground station connected straight to it pulls the whole video stream for free — and it does not count VPN interfaces (Tailscale, WireGuard, ZeroTier), whose traffic leaves again through the real uplink and would otherwise be counted twice. It resets when you say so.

          
The LTE stick reports the month it is already counting in its own flash, so the total survives a reboot or a fresh SD card and follows the billing day set in the stick's web UI. It is blind to every uplink that is not the stick — switch to a phone hotspot and this number simply stops moving.

Setup hotspot

        

          
          
        

        
        

          
          
          
        

        

          Open by default, and it runs whenever the WiFi radio is free
          
The hotspot is open by default so the captive portal can put this page in front of you with nothing to type — set a password (min. 8 characters) once the vehicle leaves the bench, and an API secret above if the network isn't yours. Since v1.41.0 it runs in always: it comes up whenever the WiFi radio is free, next to Ethernet or LTE, so you can always reach the vehicle. It can never run while the Pi is joined to a WiFi network — one radio can't do both.

Vehicle configuration

        
        

          
          
        

        

          
          
        

        

          The PCA9685 and every INA2xx ship on 0x40 — move the PCA to 0x41
          
The PCA9685 ships on 0x40 — and so does every INA2xx current sensor, which can only live at the address you give it under Telemetry. With both on the bus, move the PCA: close solder bridge A0 on its board (→ 0x41) and enter that here. It answers on 0x70 as well; that is its all-call address, not a second chip. Changing this needs a restart of the vehicle service.

        

        
Native driver modules

        
Reading module status…

        

          Installed from here — the vehicle needs internet, and it takes a minute
          
Installed here, not in a terminal. They are compiled on the Pi, so the vehicle needs internet for it (WiFi or LTE — its own hotspot has no uplink), and it takes a minute. Without the module the matching driver/sensor falls back to sim. Note that installing one builds all three: they are optional dependencies of the same package and npm always reifies them together — harmless, nothing uses a module unless you select that driver.

        

        

        


        

          
          
        

        
        

          
          
          
        

        

        

      


      

        
Telemetry (voltage / current / battery)

        

          
          
        

        
Voltage channels

        

        

        
Current channels

        

        

        

          Reference build: an INA228 on 0x40 with an R002 shunt
          
Reference build (docs/HARDWARE.md): an INA228 breakout on 0x40 with an R002 shunt — pick ina228 and the shunt, max current and range are filled in with those values. The chip supplies voltage and current, so add one channel of each with the same kind and address. Read the shunt off your own board (R001 = 0.001 Ω, R002 = 0.002 Ω) and correct the figure against a reference meter — that field is the calibration factor.

        

        

          What “primary” decides
          
The channel marked primary drives the battery %, the mAh/Wh counting, the low-battery warning and the blackbox columns. With one channel of a kind there is nothing to choose; with several, mark the one that measures the pack.

        

        
Temperature channels

        

        

        

          Optional — shown in the OSD below voltage and current
          
Optional. Shown in the OSD below voltage/current; each value can be hidden per ground device under FPV › ⚙ › Sensor values. Give short labels (T1, Motor, ESC) — they are only shown once a kind has more than one channel.

        

        

          
          
        

        
        
        

        

          Only the INA228 counts charge in hardware
          
The INA228 integrates charge and energy in hardware at ADC rate, so the mAh no longer depend on the polling rate or on samples this loop missed. Every other sensor (incl. INA237/238) is integrated on the Pi — "sensor" then falls back to "pi".

        

        

          
          
        

        
        

          This only changes the % gauge, never the mAh
          
"voltage"/"clamp" need the full & empty voltage above. mAh (consumed/remaining) is unaffected — this only changes what the % gauge uses.

        

        

          
          
        

        

      


      

        
CSI camera module

        

          Only official Pi cameras are found automatically
          
Which sensor sits on the Pi's camera port. Only the official Raspberry Pi cameras are found automatically; an Arducam needs an explicit device-tree overlay, which lives in the firmware config and is therefore only read at boot. Picking one here writes that for you — no SSH — and tells you when a reboot is due.

Checking the serial port…

          

            
            
            
          

        

        
        

          
          
          
        

        

          Reference receiver and wiring
          
Reference receiver: Adafruit Ultimate GPS v3 (MTK3339, NMEA at 9600 baud) — u-blox NEO-6/7/8/M9 and BN-880 behave the same. Wire GPS TX → pin 10, GPS RX → pin 8, GND to pin 6, and use /dev/serial0. USB dongles are easiest via gpsd. Manual home is saved; auto-home lasts for the session (takeoff point).

        

        

        

      


      

        
Design

        
        

        
        

          One choice for both halves — this page and the control app
          
The vehicle stores it and pushes it to every connected ground app, so switching here repaints the control app within a second; one that is not connected picks it up the next time it is. Light is the default — the daylight bench, a phone in the sun. Dark is the one to fly with at night, where the page sits next to live video. The video overlay (OSD) stays light-on-dark in both, because it is drawn over the picture and has to stay readable there.
